PLATE 05 TECHNICAL FAQ & TROUBLESHOOTING

Common architectural and usage questions.

How is the entire Word & PDF desktop app only 3.3 MB? +
RustPad embeds zero Chromium/WebView runtime and zero external widget toolkits. The DEFLATE/PKZIP archiver (rustpad_zip), ECMA-376 OpenXML engine (docx_io), ISO 32000 PDF 1.7 engine (pdf_create / pdf_engine), TrueType glyph rasterizer (rustpad_render), and OS window blitter (rustpad_window) compile with Thin-LTO and stripped symbols into a single self-contained native executable (including 4 fallback TrueType fonts).
Are .docx files saved by RustPad compatible with Microsoft Word and Google Docs? +
Yes. crates/docx_io writes standard ECMA-376 OpenXML packages containing [Content_Types].xml, _rels/.rels, docProps/core.xml, word/document.xml, word/styles.xml, and word/numbering.xml. Download any sample .docx in Plate 02 above to test directly in Word, LibreOffice Writer, or Google Docs.
Does PDF Redaction merely draw a black rectangle over sensitive text? +
No. Drawing a black box over a PDF stream leaves confidential strings selectable underneath. In crates/pdf_engine/src/lib.rs, applying a redaction region physically purges intersecting PdfTextItem entries from the page model before writing the permanent redaction bar into the regenerated PDF stream.
Can I compile RustPad completely offline inside an air-gapped environment? +
Yes. None of the 9 crates in Cargo.toml pull dependencies from crates.io, and the Linux backend dynamically loads libX11.so.6 at runtime so even C development headers are unnecessary. A standard Rust 1.75+ toolchain builds and passes all 13 workspace tests completely offline via cargo test --workspace.
